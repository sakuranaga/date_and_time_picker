# 祝日 CSV の読み込みと自動初期化の順序（DP-0012）

- ステータス: Implemented
- 課題: LAP DP-0012「自動初期化が holiday.csv の取得完了を待つ」
- 作成: 2026-11-09

## 1. 仕様（課題の対応案に沿う）

1. 自動初期化（`.date-picker-wrapper`）は、DOM の準備ができたら**すぐに**ピッカーを作る。holiday.csv の取得を待たない。
   取得が遅い・返ってこない場合も、ピッカーはすぐ使える（祝日の色が付かないだけ）。
2. 祝日は、取得できた時点でピッカーに反映する。開いているカレンダーはその場で描き直す（フォーカスしていた日にフォーカスを戻す）。
   閉じているピッカーは、次に開いたときに反映される。
3. カレンダーを使うモード（date / datetime）のピッカーが1つもないとき（DateTimePicker の time モードだけのページなど）は、
   holiday.csv を取得しない。
4. 取得の失敗（404、ネットワークエラー）は今と同じく祝日なしとして扱う。
5. 手動で `new DatePicker(wrapper, { holidays })` とする場合は変わらない（渡した holidays を使い、取得はしない）。
6. 両方のバンドルを読み込んだページ（DP-0011）では、DOM の準備ができた時点で読み込み順に初期化するので、
   **先に読み込んだバンドル**のピッカーが付く（今までは取得の完了順で決まらなかった）。README の記述を直す。

## 2. 設計

- `core/auto-init.js` の `autoInitWrappers`:
  - DOM の準備ができたら、空の `Set` を1つ作り、それを `holidays` として各ピッカーに渡して作る（今と同じく、印のある wrapper は飛ばす）。
  - 作ったピッカーのうち、`config.mode` が date か datetime のものがあれば `loadHolidays(csvUrl)` を始める。
    結果の各日付を同じ `Set` に追加し、各ピッカーの `refreshHolidays()` を呼ぶ。1つもなければ取得しない。
- `core/picker-core.js` に `refreshHolidays()` を追加: カレンダーを使うモードで、開いているときだけ `updateCalendar()` で描き直す。
  描き直す前にフォーカスしていた日（`_dayDates`）があれば、描き直した後にその日にフォーカスを戻す（`_focusDate`）。
  閉じているときは何もしない（開くときに `updateCalendar()` が走る）。
- `holidays` は今もピッカーが参照している `Set` なので、要素を追加すれば `isHoliday()` に反映される。
- 祝日の反映は自動初期化で作ったピッカーだけが対象（自動初期化が作った `Set` に追加する）。破棄済みのピッカーは開いていないので
  `refreshHolidays()` は何もしない。手動で作ったピッカー（独自の holidays）には触れない。
- `resolveBasePath()` は今と同じく各エントリの評価時（スクリプトの実行中）に呼ぶ。DOM の準備を待つ間に別のスクリプトが追加されても、URL は変わらない。

## 3. テスト方針

- **先に書いて失敗を確かめるテスト**（`tests/holiday-loading.test.js`。fetch のスタブを差し替えて、返すタイミングを制御する）:
  - fetch が返ってこない間も、ピッカーが作られていて、開いて日付を選べる（DatePicker、DateTimePicker）。
  - 開いている間に祝日が届くと、その場で `holiday` クラスが付き、フォーカスしていた日にフォーカスが残る。
  - 閉じている間に届くと、次に開いたときに付いている。
  - time モードだけのページ（DateTimePicker）では fetch しない。time と date が混在するページでは1回だけ fetch する。
  - fetch の失敗では祝日なしで、例外も出ない。
  - 両方のバンドルを読み込むと、先に読み込んだ方のピッカーが付く。取得は1回だけで、URL は先に読み込んだバンドルの場所から決まる
    （後のバンドルはすべての wrapper を飛ばすので取得しない）。`<head>` の `/dist/datepicker.js` と、本文の別ディレクトリの
    `/lib/sub/datetimepicker.js` の組み合わせでも同じ（配布物のテスト）。
  - 祝日が届いた後もキー操作が続く: 日付にフォーカスがある状態で届いたら、→・Enter が効く。datetime で時の項目にフォーカスがある状態で届いたら、
    フォーカス・時刻の選択・値・change の回数が変わらない（描き直すのはカレンダーだけ）。
  - 取得待ちの間に開いて destroy し、同じ wrapper に独自の holidays で手動で作り直してから取得が終わっても、例外が出ず、
    手動のピッカーの祝日（渡したものだけ）・instances・印が変わらない。
- **変わらないこと**: 既存の祝日のテスト（取得した祝日に `holiday` クラス、CSV の URL）、特性テスト、golden（開く前に取得が終わるので変わらない見込み）。
- **最後に**: ビルド → テスト全体 → 画面確認（デモで祝日が赤く表示されること）。

- 設計どおり。README の祝日の節に、読み込みを待たないこと・読み込む場所・読み込まない条件を追記した。
- golden は変化なし（開く前に取得が終わるシナリオのため）。
- 結果: ビルド → テスト全体で 232件すべて成功。画面確認（Chrome）: 日付のデモで 2026年11月の 3日・23日が赤（rgb(214, 54, 56)）、
  holiday.csv の取得は1回。datetime のデモでもピッカー3つ、取得1回。
