# 時刻の列のキーボード操作（DP-0008）

- ステータス: Implemented
- 課題: LAP DP-0008「time / datetime モードで時刻をキーボードで選べない」
- 作成: 2026-11-09

## 1. 仕様（2026-11-09 ユーザーと決定）

対象: DateTimePicker の time / datetime モードと TimePicker（時・分の列は `core/time-columns.js` で共有）。

1. **移動したらすぐ値にする**: 列の中で項目を移ると、その項目が選択され、値も変わる（クリックと同じ。1回の移動で change 1回）。
   datetime で日付が未選択のときは、今のクリックと同じく選択表示だけ変わり、値は書かない。
2. キー（時・分の項目にフォーカスがあるとき）:
   - `↑` / `↓`: 前 / 次の項目（端では止まる。止まったときは何も起きない）
   - `Home` / `End`: 先頭 / 末尾の項目
   - `→`: 時の列から分の列へ（分の列の選択中の項目にフォーカス。値は変えない）。`←`: 分の列から時の列へ
   - `Enter`: ピッカーを閉じて入力欄に戻る（値はそのまま）
   - `Esc`: ピッカーを閉じて入力欄に戻る（今の日付側と同じ）
3. **フォーカスの置き方**: 各列で選択中の項目（選択がなければ先頭）だけを Tab で止まれる項目にする（`tabindex="0"`、ほかは `-1`。roving tabindex）。
   - DateTimePicker の time モード: 開くと選択中の時の項目にフォーカス。
   - DateTimePicker の datetime モード: 開いたときは今のままカレンダーにフォーカス。Tab で時・分の列に入れる（フォーカストラップの対象に含める）。
   - TimePicker: 開く（クリック・Enter・↑↓）と選択中の時の項目にフォーカス。Esc / Enter で閉じて入力欄に戻る。
     ポップアップの外の要素にフォーカスが移ったら（Tab、Shift+Tab で入力欄に戻る、など）閉じる。入力欄での Tab は今のまま閉じて次へ。
     フォーカスが文書の外へ出ただけ（ウィンドウの切り替え、ブラウザの UI への Tab）では閉じない（今と同じ。戻ったときにそのまま続けられる）。
4. 変えないこと: マウスでのクリックの振る舞い、開いたときの書き込み（DP-0001）、丸め（DP-0002）、日付側のキー操作。

## 2. 設計

- `core/time-columns.js`（共通部品）:
  - `render()`・`select()`・`clearSelection()` で roving tabindex を保つ（各列で選択中の項目、なければ先頭が `tabindex="0"`）。
  - `focusItem(kind)`: その列の `tabindex="0"` の項目にフォーカスし、見える位置にスクロールする。
  - `keyTarget(kind, value, key)`: キーから移動先を返す純粋な処理（`{ kind, value }`、移動しないときは null）。
    `↑↓`・`Home`・`End` は同じ列の値、`→`（時の列）・`←`（分の列）は相手の列の現在の `tabindex="0"` の値。
- `core/picker-core.js`（time / datetime）:
  - 時・分の列に keydown を登録。移動先が同じ列なら `selectHour()` / `selectMinute()`（今のクリックと同じ処理）を呼んでから
    `focusItem`。相手の列ならフォーカスだけ移す。`Enter` は `hide()` して入力欄にフォーカス。処理したキーは `preventDefault`。
  - time モードの `show()` の最後で `focusItem('hour')`。
  - フォーカストラップの対象を `button:not([disabled]):not([tabindex="-1"]), [role="option"][tabindex="0"]` に広げる。
- `timepicker.js`:
  - 同じ keydown を popup の列に登録（↑↓・Home・End・←→）。`Enter` と `Esc` は popup 全体の keydown で処理し、
    `closePicker()` して入力欄にフォーカス（余白をクリックして popup 自身にフォーカスがあるときも Esc が効くように）。
  - `openPicker()` の最後で `focusItem('hour')`。
  - 閉じる判定は document の `focusin`: 開いているとき、フォーカスが入った要素が popup の外なら `closePicker()`。
    入力欄・外の要素への Tab、Shift+Tab で時 → クリア → 入力欄、スクリプトによる外へのフォーカスで閉じる。
    フォーカスが文書の外へ出るだけ（ウィンドウの切り替え、ブラウザの UI への Tab）では、文書内で focusin が起きないので閉じない（仕様 3）。
    余白やスクロールバーのクリックでは、フォーカスが popup の外の要素に入ることはないので閉じない（外側のクリックは今のまま overlay が閉じる）。
    この document のリスナーは保存しておき、`destroy()` で外す。
  - popup 自体をフォーカス可能にする（`tabindex="-1"`。Tab では止まらない。`:focus` の枠線は CSS で消す）。余白をクリックしたとき、
    多くのブラウザではフォーカスが popup に移り、Esc が popup の keydown に届く。ブラウザによって body に移る場合に備え、popup の click
    （今も伝播を止めているハンドラー）で、フォーカスが popup の外にあれば `popup.focus({ preventScroll: true })` で popup に戻す。
  - popup は Tab で外へ出られる非モーダルな作りになるので、`aria-modal="true"` を外す（`role="dialog"` と `aria-label` は残す）。
- ARIA: 列は今のまま `role="listbox"`（`aria-label` あり）、項目は `role="option"` と `aria-selected`。

## 3. テスト方針

- **先に書いて失敗を確かめるテスト**（`tests/time-keyboard.test.js`）。DateTimePicker の time モード、datetime モード、TimePicker で:
  - 開いたときのフォーカス（time / TimePicker は時の 10、datetime はカレンダーのまま）。
  - roving tabindex: 各列で `tabindex="0"` はちょうど1つで、選択中の項目。クリアの後は先頭。
  - `↓` → 11 が選択・フォーカス、値 `11:00`、change 1回。`↑`×2 → 09。`Home` → 00、`End` → 23、`End` の後の `↓` では何も起きない（change なし）。
  - `→` → 分の列の選択中の項目にフォーカス（値は変わらない）、`↓` → 30、`←` → 時の列へ。
  - `Enter`・`Esc` → 閉じて入力欄にフォーカス、値はそのまま。
  - datetime: 日付未選択で `↓` → 選択表示だけ変わり、値は空、change なし。フォーカストラップの対象に時・分の項目が入る。
  - TimePicker: ポップアップの外の要素（外の要素、入力欄）にフォーカスが入ると閉じ、overlay も消える。ポップアップの中の移動
    （時 → クリア、項目 → popup 自身）や、フォーカスが外れるだけ（`blur()` で body に移る）では閉じない。popup 自身にフォーカスがあるときの Esc で閉じる。
    popup は `tabindex="-1"` で、`aria-modal` がない。`destroy()` の後は document の focusin で何も起きない。
    popup の余白をクリックしたとき、フォーカスが popup の外（body）なら popup に戻り、その後の Esc で閉じる。
  - 既存テストの更新: `tests/datetime-focus.test.js` の Tab のテストは、フォーカストラップの最後が「最後のボタン」である前提なので、
    新しい対象（最後は分の項目）で、分の項目 → 先頭、先頭で Shift+Tab → 分の項目の折り返しを確かめる形に変える。
    理由はレビュー記録に書く。テストのキー送信はイベントを発火するだけでブラウザのフォーカス移動は起きないので、
    実際の Tab の順番（カレンダー → 時 → 分）は画面確認で見る。
- **変わらないこと**: 既存の特性テストはそのまま通る。golden は time / datetime / TimePicker の記録で DOM（tabindex）とフォーカスが変わる見込み。
  作り直して、差分がこの仕様の範囲（フォーカス、tabindex）だけであることを確かめる。date の記録は変わらないこと。
- **最後に**: ビルド → テスト全体 → 画面確認（実ブラウザ）。time のデモと TimePicker のデモで ↑↓←→ Enter Esc Tab Shift+Tab、
  datetime のデモで Tab の順番（カレンダー → 時 → 分 → 先頭へ）。TimePicker で、popup の余白のクリック・列のスクロールバーの操作の後も閉じず、
  その後 Esc で閉じられること、外の要素へ Tab すると閉じること。

## 実装時の差異

- TimePicker の列の click は伝播を止めず、popup の click で止めるようにした（列の余白のクリックでもフォーカスを popup に戻すため。
  コードレビュー第1回）。
- TimePicker の Enter は、項目か popup 自身にフォーカスがあるときだけ閉じる（クリアボタンの Enter はボタンの動作のまま）。
- golden: 時刻まわりの3記録を作り直し。変わったのはフォーカスと DOM（tabindex、TimePicker の popup の属性）だけで、値・change・開閉は不変。
- 結果: ビルド → テスト全体で 212件すべて成功。画面確認（Chrome、実際のキー操作）:
  - TimePicker: クリックで開くと時にフォーカス、↓↓→↓ で 12:15、余白のクリックでフォーカスは popup 自身に移って開いたまま、Esc で閉じて入力欄へ、
    Enter で開いて Tab で時 → 分 → 外の欄（閉じて overlay も消える。外の欄は開かない）。
  - datetime: カレンダーの最後の日 → Tab → 時 → 分 → 先頭（フォーカストラップ）。
- 範囲外で気づいたこと: カレンダーの日付は今も全部が Tab で止まるので、datetime で時刻に着くまでに Tab をその月の日数分押す必要がある
  （日付側の roving tabindex は別の改善として扱う）。
