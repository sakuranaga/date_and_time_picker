# 入力済みの値の読み込み（DP-0007）

- ステータス: Reviewed
- 課題: LAP DP-0007「既存の input の値を読み込まず datetime では時刻を選んでも値が変わらない」
- 作成: 2026-11-09

## 1. 仕様

課題の対応案（初期化時と開くときに input の値を解釈し、選択状態に反映する）に沿って決める。今の振る舞いを変えるのは、
input に値が入っているのにピッカーがそれを知らない場合だけにする。

1. **対象**: DatePicker と DateTimePicker（date / datetime モード）。初期値は input の `value`（HTML の `value` 属性、
   またはスクリプトで設定した値）。新しい属性（README の TODO にある `data-value`）は作らない。
   time モードと TimePicker は、開くときに値を読む処理がもうあるので変えない。
2. **読み方**: 値が `format`（`data-format`。既定 `YYYY/MM/DD`）どおりの日付なら、その日を選択状態にする。datetime は
   「format の日付」または「format の日付 + 半角スペース + HH:mm」（DP-0006 と同じ形）。存在しない日付（2026/02/31 など）は読まない。
3. **読めない値**（空、別の形、存在しない日付）: 日付の選択はなし。**input の値は書き換えない**。
4. **いつ読むか**: 生成時と、開くとき（`show()`）。開くときは、値の日付が今の選択と違う日のとき（または値が空になったとき）だけ反映する。
   値の日付が今の選択と同じなら何もしない（今までどおり、月を移動して閉じて開き直したときは、その月のまま）。
5. **表示する月**: 値から新しく日付を選択状態にしたときは、その日の月を表示する（例: `2025/12/01` が入っていれば 2025年12月）。
6. **範囲外の日付**（min/max の外）: 読んだとおり選択状態にする（カレンダーでは選択表示のまま無効のマスになる）。値は書き換えない。
7. **datetime の時刻**: 開いたときの時刻の読み取りは DP-0006 のまま（format の日付 + HH:mm の形のときだけ）。日付を読めた場合、
   開いたときの書き込み（DP-0001 の「開いたら1回書き込む」）が日付と時刻で行われ、値は同じ形で書き直される（change 1回）。
   これで、課題の「時刻を選んでも値が変わらない」が直る（日付が選択状態になるので、時刻のクリックで値が更新される）。
8. README の TODO の「初期値設定（`data-value` 属性）」は、input の `value` で設定できるようになったので、使い方の説明に置き換える。

## 2. 設計

- `core/date-utils.js` に `parseFormattedDate(text, format)` を追加: `^${datePattern(format)}$` に一致し、年・月・日が
  実在する日付なら `Date`（0:00）を、そうでなければ null を返す。日付は `new Date(2000, 0, 1)` に `setFullYear(y, m - 1, d)` で
  組み立て、年月日が一致するかで実在を確かめる（`new Date(y, ...)` は 0〜99年を 1900年代にしてしまうため使わない）。
  `datePattern` の3つのグループの並びは format の中のトークンの順番で決まるので、トークンの位置から年・月・日のグループを対応づける。
  format に `YYYY`・`MM`・`DD` のどれかがない場合は読まない（null）。
- `core/picker-core.js`:
  - `_dateFromInput()`: date モードは値全体を `parseFormattedDate(value, format)`。datetime は、値が「日付 + 空白 + HH:mm」なら
    日付部分を、そうでなければ値全体を `parseFormattedDate` で読む。
  - `_syncFromInput()`: date / datetime のとき、`_dateFromInput()` の結果を今の `selectedDate` と比べ、違う日なら
    `selectedDate` をそれにし、`viewDate` をその日にする。値が読めず、`selectedDate` があるときは `selectedDate = null`
    （viewDate はそのまま）。同じ日なら何もしない。
  - 生成時（`init()` の最後）と `show()` の最初（カレンダーを描く前）に `_syncFromInput()` を呼ぶ。
- TimePicker と time モードは変更しない。

## 3. テスト方針

- **先に書いて失敗を確かめるテスト**（`tests/read-input-value.test.js`）:
  - date モード（DatePicker、DateTimePicker）: `value="2025/12/01"` の input で開くと 2025年12月を表示し、1日が選択状態、クリアが有効。
  - `data-format="YYYY-MM-DD"` と `value="2025-12-01"` でも同じ。format と違う形（`2025/12/01`）は読まない（選択なし、値は残る）。
  - datetime: `value="2025/12/01 10:00"` で開くと 12/1 が選択、時刻 10:00 が選択、値は `2025/12/01 10:00`（change 1回）。
    時をクリックすると `2025/12/01 14:00` に変わる（課題の症状）。
  - datetime: 日付だけの `value="2025/12/01"` でも 12/1 を選択し、開いたときに現在時刻付近を付けて書き込む。
  - 開いたままではなく、閉じている間にスクリプトで値を変えて開くと、その日に移る。値を空にして開くと選択がなくなる。
  - 読めない値（`abc`、`2026/02/31`、`2026/1/5`（MM が2桁でない））: 選択なし、値は書き換えない、change なし（date モード）。
  - 範囲外（`data-max-date="2025-11-30"` と `value="2025/12/01"`）: 選択状態だが無効のマス、値はそのまま。
  - 値と同じ日が選択済みのとき、月を移動して閉じ、開き直すと、移動した月のまま（今の振る舞いを変えない）。
- 生成時の読み込みを単独で確かめるテスト: 初期値付きで生成した直後（開く前）に `selectedDate`・`viewDate` が値の日付になり、
  input の値は変わらず、change は0回。
- 同じ日の判定: 今日ボタンで選んだ日（時刻付きの Date）と、値から読んだ同じ日（0:00）を同じ日とみなし、月を移動して閉じ、
  開き直すと移動した月のまま。
- 単体テスト: `parseFormattedDate`（各 format、トークンの順番、存在しない日付、1桁の月日、年の桁数（0年・99年・100年・10000年）、
  トークンが欠けた format）。
- 既存テストの変更: `tests/datetime-format.test.js` の「コロンを含む format で日付だけの値」のテストは、今は「日付は未選択なので
  書き込まない」を確かめている。この仕様では日付（2026/01/30）を読み、開いたときに現在時刻付近を付けて書き込む（change 1回）ので、
  期待値をそれに合わせて変える。日付の `01:30` を時刻と読まないこと（時の選択が 10）の確認は残す。理由はレビュー記録に書く。
- **変わらないこと**: 既存の特性テスト・golden の date の記録（値を外から入れるシナリオがない）。golden の datetime の記録は、
  外から値を入れて開くステップ（`"2026/01/07 08:30"` など）で、日付が選択状態になり書き込みと change が起きるので変わる見込み。
  作り直して、差分がこの仕様の範囲だけであることを確かめる。
- **最後に**: ビルド → テスト全体 → 画面確認（デモの input に value を入れた状態で開く。ブラウザのコンソールから値を入れて確認）。
